# kukuri

kukuri は、興味のある話題から人やコミュニティにつながる、トピック中心のP2Pソーシャルアプリです。公開の会話に参加したり、同じ話題の中で小さな非公開チャンネルへ移ったりしながら、自分の端末を基点にアカウントと自分の投稿を保持できます。

![タイムライン、スレッド、プロフィールの3カラムとコントロールセンターを表示した kukuri デスクトッププレビュー](./docs/assets/readme/kukuri-desktop-preview.png)

## kukuri でできること

- 興味のあるトピックを見つけ、投稿や返信でスレッド形式の会話に参加できます。
- コミュニティを別々の場所へ分断せず、同じトピック内で公開投稿と非公開チャンネルを使い分けられます。
- フォロー、リアクション、再投稿、引用、ブックマークを利用し、見たくない投稿者は自分の端末上でミュートまたはブロックできます。ブロックすると投稿は双方向で非表示になります。
- 同意したコミュニティノードのコミュニティインデックスで、投稿やトピックを検索・発見できます。
- 相互につながった相手と DM を交わし、画像や動画を共有できます。
- 返信、メンション、フォロー、再投稿、メッセージをアプリ内通知や OS 通知で確認できます。
- アカウント鍵をパスフレーズ付きで暗号化してエクスポートし、別の端末でインポートできます。複数アカウントは再起動なしで切り替えられます。
- 1 アカウントを暗号化された 1 ファイルへバックアップし、別の端末で復元できます。
- 日本語・English・简体中文の表示と、ライト／ダークテーマを選べます。
- 再起動、一時的なオフライン、プレビュー版の更新を挟んでも、アカウント、自分の投稿、端末内の状態を引き継げます。

## 3 分で試す

1. Windowsプレビュー、公開済みの[Linux AppImage](docs/runbooks/linux-appimage-smoke.md)／[Deb](docs/runbooks/linux-deb.md)、または[ソース実行](#開発クイックスタート)で起動します。CLI専用profileは[Linux CLI手順](docs/runbooks/linux-cli.md)を参照してください。
2. 最初の画面で言語を選び、18 歳以上であることを確認し、アプリの利用規約とプライバシーポリシーに同意します。同意するまで kukuri はネットワーク接続を開始しません。
3. 「コミュニティノードとは？」を読み、「規約を確認する」からそのノードの文書に同意します。接続準備はこの明示的な同意の後にだけ始まります。「あとで」を選んでも、見つけるまたはコミュニティノード設定から再開できます。
4. プロフィールカラムを開き、表示名、ユーザー名、自己紹介を設定します。
5. 最初から用意されたトピック（`kukuri:topic:general`、`kukuri:topic:dev`、`kukuri:topic:test`）を開き、公開投稿を 1 件作成して既存の投稿へ返信します。
6. タイムラインカラム上部の「プライベートチャンネル」ボタンから、同じトピックの中で非公開チャンネルを作成するか、既存のチャンネルへ参加します。
7. 下部バーの「フィードバックを送る」（テスターフィードバックを受け付けるコミュニティノードへ送信）または GitHub からフィードバックを送ります。診断レポートを添える場合は、`設定 → 開発者` で開発者モードを有効にしてから、`設定 → リリース` でレポートをコピーまたは書き出します。

既定の診断レポートには、秘密鍵、認証トークン、非公開チャンネルの秘密情報、招待・共有トークン、DM 本文、ローカルデータベースのパスを含めません。

## プレビューの状態と制限

- 配布対象はWindows NSIS、Linux x86_64 AppImage／Deb、Linux x86_64／aarch64 CLIです。実際の提供状況は公開Releaseの成果物一覧を正とし、生成成功だけを公開済みと扱いません。Debの更新は明示適用とOS権限承認が必要で、取消後に別認証を自動要求しません。macOSはパッケージ未提供です。
- 初回起動では年齢の自己申告とアプリ規約への同意が必要です。さらに各コミュニティノードは、利用前にそのノード固有の文書への明示的な同意を求めます。成人向けとラベル付けされた投稿は、`設定 → セーフティ` で許可するまで非表示です。
- DM の確認には、別のテスト用ピアと相互関係が必要です。P2P の動作は、2 台の端末またはデータ領域を分けた 2 つのアプリで確認しやすくなります。
- Live、ゲーム、Stream、Metaverse の各画面は既定では表示されず、`設定 → 開発者` で開発者モードを有効にした場合にだけ現れます。Metaverse の Dome（Dome ホスティング、シームレス遷移、空間音声、追従カメラ、接続マップ、Dome 管理）は実験機能で、データ形式の後方互換 decode や移行は保証しません。Stream にはまだメディアプレーヤーがありません。
- アカウント鍵は自分の端末にだけ保存されます。中央での再発行や復旧はないため、暗号化した鍵のエクスポートか端末バックアップで控えを残してください。
- プレビュー版の更新では、アカウントを識別する鍵、プロフィール、フォロー関係、自分の投稿、端末内データベース、Irohのデータ、コミュニティノードの設定、非公開チャンネルの権限情報、通知一覧を保持する前提です。端末バックアップはコミュニティノードのトークン、同意状態、年齢申告、成人向け表示設定を移行しないため、復元後にやり直します。端末内の状態を残したい場合は、アンインストールやリセットの前にバックアップを作成してください。
- テスト中のソフトウェアです。接続、更新、復旧の問題を報告するときは、秘匿情報を除去した診断レポートを添付してください。

現在のマイルストーンは [Builder Preview 計画](./docs/progress/2026-04-16-mvp-builder-preview-plan.md)、各プレビューリリースの変更は [CHANGELOG](./CHANGELOG.md)、配布とデータ安全性の検査は[リリース手順書](./docs/runbooks/release.md)を参照してください。

## kukuri の仕組み

- **アカウントと自分の投稿は利用者のものです。** アカウントを識別する鍵は自分の端末に保存します。コミュニティノードはアカウントの所有者でもホームサーバーでもありません。
- **P2P が基盤です。** 通信は Direct P2P、Relay Supported P2P の順に優先し、それらでデータを運べない場合だけ Relay Fallback を使います。
- **コミュニティノードの支援範囲は限定されています。** ノードは初期接続、認証、トピックの合流支援、接続、索引、モデレーション、通報などを補助できます。一方、利用者の投稿、プロフィール、フォロー関係を恒久的に保管する中心ではなく、ネットワーク全体への権限も持ちません。
- **データの種類ごとに経路を分けます。** 構造化された共有状態は `docs`、メディアや大きなデータは `blobs` で同期します。`hints` は同期が必要かもしれないことをピアへ知らせるだけです。
- **Nostr互換は意図的に限定しています。** アカウントを識別する鍵、署名付きデータ、一部タグの有用な意味づけを利用しますが、完全なNostrクライアントではなく、内部同期も中継優先ではありません。
- **モデレーションの効力は発行元の範囲に閉じます。** モデレーションイベントや安全性の勧告は、発行したノードからの任意の信頼情報であり、ネットワーク全体への命令ではありません。適用方法は各クライアントが判断します。

恒久的な責任境界は [P2P-first Community Node の責任境界](./docs/architecture/p2p-first-community-node-responsibility-boundary.md)に記載しています。

## 今後の方向性

- 検索、発見、推薦、ゲートウェイ、ブリッジは、P2P の中核に必須の正本を置かず、任意のサービスとして拡張できます。
- Community Node の信頼、モデレーション、ポリシー支援、運用者向け機能は、各ノードが宣言した能力と権限の範囲内で発展させられます。
- Live、ゲーム、Stream、Metaverse は実験機能として承認・実装済みです（ADR 0035〜0045）。製品スコープへ昇格させる際も、トピック中心の所有権と同期境界は変えません。

これらは方向性であり、現在のプレビューですべて利用できるという約束ではありません。

### 開発クイックスタート

必要な環境:

- Git
- `rust-toolchain.toml` で固定された Rust `1.98.1`
- Node.js `^20.19.0` または `>=22.12.0`
- 以下のコマンドから利用する pnpm `10.16.1`
- [開発手順書](./docs/runbooks/dev.md)に記載された環境別の依存パッケージ。Windows 開発には [Tauri の事前要件](https://v2.tauri.app/start/prerequisites/#windows) も必要です
- Docker は Community Node の統合テストとローカル Community Node 構成を使う場合のみ必要です

```bash
git clone https://github.com/kukuri-app/kukuri.git
cd kukuri

npx pnpm@10.16.1 install --dir apps/desktop
cargo xtask doctor

cd apps/desktop
npx pnpm@10.16.1 tauri:dev
```

通常の検査はリポジトリのルートで実行します。

```bash
cargo xtask check
cargo xtask test
cargo xtask e2e-smoke
```

ブラウザー上で確認する UI 変更では `cargo xtask desktop-ui-check` も実行します。ブラウザー上のフロントエンドだけを扱う場合は `npx pnpm@10.16.1 --dir apps/desktop dev` を利用できます。対象別の検査、UI 検証、Community Node の作業手順、環境ごとの設定は[開発手順書](./docs/runbooks/dev.md)にまとめています。
