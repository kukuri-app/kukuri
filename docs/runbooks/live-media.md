# live の映像・音声の確かめ方

正本は [ADR 0067](../adr/0067-media-transport-moq.md)（#1034）。映像は画面（webview）の `getUserMedia`・`getDisplayMedia`・WebCodecs（VP8）で取り込み・復号し、音声は Rust 側（[空間音声](metaverse-spatial-audio.md)と同じ機器の経路）で扱う。配信者の端末は視聴者 4 人まで直接送り、5 人目からは視聴中の視聴者が 2 人まで転送する（配信者の署名を確かめ、中身を変えずに渡す）。確かめるのは OS の標準の入出力の境界と、視聴者の画面の canvas まで（#1800）。

## 自動の試験

`apps/desktop/tests/real-app/scenarios/live.mjs`（LV-1〜LV-9・LV-11〜LV-13。配信者 H・視聴者 V1・V2）と `live-relay.mjs`（LV-10。H・V1〜V5）。部品は `live-media.mjs`。動かし方は [dev.md](dev.md) の「実際のアプリを複数動かす自動の試験」。CI では Linux package と windows-fast で、関係する PR ごとと毎晩に動く。

- 取り込み: camera は、webview の取り込みの API が返す映像を試験の映像（canvas）に置き換える（API は本物を呼び、許可の経路を通す）。画面は Windows では本物（画面全体の自動の選択）で、Linux の CI には画面の取り込みの portal が無いので置き換える。選択の取り消しは API の拒否で模擬する。Linux の webview の疑似 camera（inspector で有効にする）の frame は encode できないので、映像には使わない。
- 映像: 視聴者の canvas に描かれた frame（描いた時刻・画素の色・大きさ）を記録して確かめる。
- 音: 空間音声と同じ仮想の入出力（Linux は instance ごとの PulseAudio の null sink、Windows は VB-CABLE の共有と process ごとの音声 session の peak）。LV-3 は instance ごとの入出力が要るので Linux だけで確かめる。

| 項目 | 確かめること | 観測 |

Web（#1879）は、実ブラウザの E2E（`apps/desktop/tests/web-e2e/main-flow.mjs` の `live`。動かし方は [dev.md](dev.md) の「Web の build と実ブラウザの主要導線の試験」）で確かめる。Chrome の偽の camera・mic（起動の引数）を使い、Chrome だけで、PR の CI の merge の条件にする（2026-10-19 のユーザー判断）。Web が Live を作って配信し、native の相手（harness の `web_e2e_fixture` の `/fixture/live-watch`）が映像の keyframe と、映像の時刻に追いつく音声の再生時刻を受ける。別の Web は live の列から参加すると、canvas に映像が描かれ、音がブラウザの出力へ渡り（出力へつなぐ node の後ろの音の大きさを page で測る）、音量 0 で無音になり、退出で描画が止まる。mic を止めた後に始めた視聴は音声の再生時刻が映像に追いつかず、戻すと追いつき、配信を止めると視聴が終わる。公開スレッドで始めた Live は、Web の公開スレッドの一覧に配信中の印が付き、終わると消える。

## 既知の制約

- 直接の視聴者は 4 人まで、各視聴者が転送するのは 2 人まで。参加の問い合わせが 16 段で尽きると「視聴の空きが見つからないため参加できません」と出て、5 秒ごとに試し直す。
- 転送する視聴者は、上り回線を子の数 × 配信の bitrate（最大約 5 Mbps）使う。
- 配信できるのは、この端末で作った session だけ（manifest の配信者の端末の id）。
- 配信は主催者の card から始め、配信中の操作は shell の上部の bar にある（#1839）。主催者が live の列を離れても（列を閉じる・別の画面へ移る）配信は続き、bar の停止、live の終了で止まる。この端末から同時に配信できるのは 1 つだけ。
- Windows の WebView2 は camera の許可を保存するので、一度 camera で配信した後は、移行用の QR の読み取り（#1628）でも camera の確認が出ない。
- Linux（WebKitGTK）の decoder は、配信の途中で映像の大きさが変わっても最初の大きさで出す（camera から画面へ切り替えると、画面は camera の大きさに縮んで描かれる）。
- 配信者の app が配信中に止まると、視聴者が気付いて参加し直すまで約 35 秒、描画に戻るまで約 1 分かかる（2026-10-14 の測定）。
- 版の違う kukuri の間では映像・音声が届かない（ADR 0067 §1）。
