# kukuri アプリ データフロー突合表

最終更新日: 2026-10-09
対象: kukuri デスクトップアプリとインストール不要の Web クライアント（#1220）、legal bundle version 10

この表は、`docs/legal/privacy-policy.md` と `docs/legal/external-transmission-notice.md` を現行実装へ照合するための記録である。各 Community Node が独自に処理する内容は、その Node の manifest と公開文書を正とする。

| DHT・P2P・relay 通信 | runtime の discovery／connection state | Mainline DHT、接続 peer、構成された iroh relay。経路は `Direct P2P -> Relay Supported P2P -> Relay Fallback`。Web は relay へ WebSocket で接続し、peer とは WebRTC の DataChannel で通信する。Web との WebRTC の交渉では、relay と同じ host の STUN（3478 番）へ認証の無い binding を送り（IP address とポートが届く。relay を使わないときは送らない）、接続の候補（端末の IP address とポート）を交渉の相手へ送る（native も Web と接続するときは同じ） | 到達先探索、hole punching、P2P transport、成立しない場合の実データ中継 | DHT／peer／relay 側の保持方針に従う。relay URL があるだけでは実データ fallback を意味しない | `crates/transport/src/iroh/**`、`crates/webrtc-transport/src/signaling.rs`、ADR 0057 §6、`docs/architecture/p2p-first-community-node-responsibility-boundary.md` |
| カスタムリアクションとそのセット（#1232） | 自作の asset と作ったセットの一覧の record（名前・件数・セットの hash・作成時刻）は author-owned public docs replica。画像とセットの中身は content-addressed blob（セットは名前と、画像の hash・検索名・形式・大きさ・最初の作者の公開鍵の並びの JSON で、署名は無い）。保存済みの一覧は account DB（`kukuri.db`、Web は IndexedDB）だけ | asset と一覧の record は同じ author replica を取得する P2P peer。画像・セットの blob は hash を求めた P2P peer（公開投稿に貼られたセットと、自作・保存済みの画像は前の行の公開コンテンツの発見の対象）。セットの共有用の文字列 `kukuri:reaction-set:<hash>` は利用者が投稿・DM に貼った範囲 | リアクションの作成・再利用と、複数のリアクションの共有・取り込み | 受信 peer が copy を保持し得る。取り込んだ人の端末はセットの blob を cache に置く。保存済みの解除は端末内の行を消す | ADR 0017 §2.4–2.6、ADR 0063 §1、`crates/app-api/src/{reactions.rs,reaction_sets.rs}` |
| 公開コンテンツの発見（#1632。native。Web は次の行） | 告知の対象は account DB（`kukuri.db`）の公開 blob の参照の索引（検証済みの公開記録を書く transaction で記録ごとに置き換える）と告知の予定（公開の参照と返せる保持の両方がある hash だけ、512 件まで）。DHT・補助 index で見つけた保持端末の候補と照会の結果は memory だけに持つ | 設定「公開コンテンツの発見」がオン（既定）の間、Community Node 利用中・`static_peer` でも Mainline DHT へ UDP で参加する（通信元 IP address・UDP port が DHT 参加者から観測可能。署名済み address record の公開・解決も行う）。保持する公開 blob（公開投稿の本文・添付・repost の添付・リンクプレビュー画像・本文に貼られた custom reaction のセット、プロフィール画像、公開 topic の custom reaction 画像、自作・保存済みの custom reaction 画像（セットから取り込んだものを含む））の BLAKE3 hash から導いた infohash を約 10 分ごとに告知し、手元・既知の相手に無い公開 blob の infohash で保持端末を検索する。kukuri が運用する補助 index（kukuri の鍵で署名した一覧の最大 2 台）へ、DHT の UDP の送信元 address と endpoint ID を結び付けた署名つき record を約 30 分ごとに登録し、検索で見つけた IP address・port を照会して endpoint ID を得る。取得は既存の P2P 取得（hash の検証つき）。DM・private channel・非公開の内容の hash と blob の中身は送らない | 手元と既知の相手に無い公開 blob の保持端末の発見と、保持する公開 blob の提供 | 保持しなくなった・公開でなくなった hash は告知の更新を止め、DHT 上の告知と補助 index の record（既定 1 時間）は期限で消える。DHT 参加者の保持は kukuri が一括して削除できない | `crates/iroh-node/src/public_blobs.rs`、`crates/store/src/sqlite/public_blobs.rs`、ADR 0008／0063 |
| 公開 blob の保持端末の検索（#1632。Web） | 検索の対象は、Web の account の database（IndexedDB）の公開参照の索引（`public_refs`。native と同じ範囲（自作・保存済みの custom reaction 画像を含む）を、その記録を書く transaction で記録ごとに置き換え、導入前の行は小分けに取り込む）。Node が返した候補は memory（取得元の候補表、期限 10 分）だけに持つ | 検索を提供すると bootstrap で示した利用中の Community Node だけ（同意・認証の後）。手元と既知の相手に無い公開 blob の BLAKE3 hash と取得に残る時間（`POST /v1/blob-providers/search`。上限 8 秒）を送り、relay URL を持つ保持端末の endpoint ID・relay URL・直接の address（最大 4 件）を受け取る。Node はその hash から導いた infohash で Mainline DHT の保持端末を探し、見つけた IP address・port を補助 index へ照会する（blob は取得・保存しない）。取得は既存の P2P（relay・WebRTC、hash の検証つき）。DM・private channel・非公開の内容の hash は送らない | 手元と既知の相手に無い公開 blob の保持端末の発見 | Web は候補を期限で捨てる。Node 側の扱いは、その Node のプライバシーポリシー・外部送信表示（capability `public_blob_search`）に従う | `crates/desktop-runtime/src/community_node/public_blob_search_support.rs`、`crates/web-runtime/src/account/public_refs.rs`、`crates/cn-user-api/src/blob_providers.rs`、ADR 0063 §7・§8 |

## 確認上の境界

- `api.kukuri.app` は現行配布物の初期候補であり、汎用 runtime の固定宛先ではない。利用者は候補を削除・置換できる。
- `iroh-relay.kukuri.app` を含む relay URL は、選択した Node の connectivity metadata や runtime config から得る。任意 Node が別の relay を提示し得る。
- Community Node 運営者と kukuri 運営者が同一とは限らない。Node ごとの受信項目、保持、外部送信、削除・通報は当該 Node の公開文書を確認する。
- P2P で受信済みの第三者 copy、第三者 Node の index／cache、経路事業者の log を kukuri アプリから一括消去することはできない。
- Web の秘密の出口の照合（#1220 AC-6、2026-10-04）: URL: 移行の招待の秘密はリンクの `#` 以降にあり（#1211 AC-1）、Web では貼り付けるか、移行元の QR をカメラで読んで受け取るので、page の URL・HTTP の要求・Referer に出ない。カメラの映像は読み取りの間だけ memory の canvas で読み、保存・送信しない（#1628、ADR 0062 §1）。cookie は読み書きしない（Community Node の認証は request の header の token）。analytics・第三者の script は読み込まない（配信の CSP が `script-src 'self'` で拒む）。公開索引へ送るものは native と同じ公開の投稿・profile の範囲で、鍵・capability を含めない。診断レポートとアプリ内ログの規則は native と同じで、アプリ内ログは Web に無い。
