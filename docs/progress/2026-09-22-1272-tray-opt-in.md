# Issue #1272 タスクトレイ格納のopt-in化

## 対象

- Issue: #1272
- Scope revision: `1272-plan-v1`
- 基準commit: `b39d3b606d835aaae9580b13b85d3742e78cb2b6`
- リスク区分: C
- UI変更分類: 既存画面の改善 + close flowの利用者向け挙動変更

## 目的と対象外

main windowを閉じた利用者が、意図せずprocessを残さないようにする。close設定が未選択なら終了かtray格納かを確認し、明示的に記憶した場合だけ以後の動作を固定する。設定はControl Centerのシステム面から変更できる。

自動起動、最小化button、tray menu全体、P2P shutdown処理の再設計は対象外。

## AC / INVARと実装

| 条件 | 実装・証跡 |
| --- | --- |
| AC-1 | Tauri `WindowClosePreference`の`null`を確認要求へ変換し、確認前のhide／shutdownを禁止するunit test |
| AC-2 | 保留要求ID、frontend Dialog、記憶checkbox、保存失敗時の再試行をTauri／Vitestで検証 |
| AC-3 | `window-close-preference.json`の原子的保存・再読込とControl Center「システム」の選択操作 |
| INVAR-1 | 選択後も既存`request_exit`を使用し、保留要求を単発consume |
| INVAR-2 | tray Quit、signal、update restartはclose preference commandを経由しない |
| INVAR-3 | `tray`選択時も既存のtray登録確認とLinuxのhidden tray監視を維持 |
| INVAR-4 | 設定はapp data directoryのLocal Only JSONで、runtime／network APIに依存しない |

## Inventory / transition差分

- 追加入口: close確認の応答、close preferenceの取得・保存、Control Center「システム」。
- 追加sink: Local Only preference JSONのread／atomic replace。
- 既存sink: window hide、host shutdown、process exitは変更せず、設定または保留要求の応答が前段を支配する。
- 上限: 保留close要求は1件だけ。close連打は同じ保留状態へcoalesceし、総要求数に比例するqueueを持たない。
