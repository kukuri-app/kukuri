## #1904 の配布物での確認

詳細は #1904 の本文。

- desktop（NSIS の `kukuri-desktop-tauri.exe`・Store の `kukuri.exe`・Deb の `kukuri-desktop-tauri`）、Linux CLI（x86_64）、CN の 4 image の binary は、どれも rustls-webpki 0.103.16 の不信頼の公開鍵 8 件を含み、webpki-roots 1.0.9 にあった emSign ECC Root CA - G3 の公開鍵を含まない。v0.4.7 の CN の binary は、不信頼の公開鍵を 1 件も含まず、emSign の公開鍵を含む。
- CN の image の中では、curl も、製品と同じ版の crate で build した probe も 12 経路を拒否し、有効な host には接続できた。
- 配布 CLI（emSign ECC Root CA - G3 と Comodo AAA Services root を含む古い CA の Debian 上）: 0.4.7 は 2 経路で handshake を終えて要求を送った。0.4.8 は証明書を受けた直後に alert を送って切断し、daemon の再起動後も同じだった。`api.kukuri.app` の規約文書は再起動の前後とも取得できた。
