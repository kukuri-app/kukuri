- 4 つとも registry で解決した digest で、OCI revision は `bba0b3af`。relay の image に `/usr/local/bin/cn-stun` があることを確かめた。
- CN 側の差分（`9c48cf34` から）: CN の Postgres の migration は無し。STUN の container（#1483）と GCP の firewall（udp 3478）、user-api の CORS の許可 origin。
- **backup**: `gs://kukuri-cn-pg-backup/postgres/2026/10/06/031456.dump`（generation `1791256497817371`、920,155 bytes）。反映直前に `kukuri-backup.service` で取得した。
- **Terraform**
  - 最初の plan は、firewall `kukuri-cn-allow-stun` の追加と、`metadata_startup_script` だけを理由にした VM の置き換え。
  - startup script の中の差分は、4 image の digest・user-api の CORS の環境変数・`cn-stun` の service・`operator-config.yaml`・deployment revision だけだった。
  - metadata を同期した後の plan は firewall の追加だけで、それを apply した。最後の plan は No changes。
- **startup の再実行**: `bootstrap complete` の後、container が新しい digest で起動した。
- **一時の停止（約 3 分、03:17:55〜03:20 UTC）**: `operator-config.yaml` の `deploy` に `cors_allowed_origins` を足したところ、配置した user-api（#1618 より前の source）が知らない項目として設定の読み込みを拒み、起動できなかった。
  - VM の上の file からその項目を除いて user-api を起動し直し、続けて元の `operator-config.yaml` からも除いて metadata を同期し直した（desired・metadata server とも SHA-256 `0e4abf23…`）。startup をもう一度実行し、全 container が起動した。
  - CORS の値は tfvars（`cors_allowed_origins`）から環境変数で渡る。`operator-config.yaml` に書けるのは、#1618 を含む image を配置した後。
- **readiness**: `ready=true fail=0 unknown=0`。
- **公開面**: healthz・manifest（`/v1/node/manifest`、`/.well-known/kukuri/community-node.json`）・relay の ping は HTTP 200。node_id `6e6272c8…` と policy snapshot `6e8ed88d…` は変わらず、再同意は発生しない。
- **CORS**: `https://app.kukuri.app` からの preflight に `Access-Control-Allow-Origin: https://app.kukuri.app` が返り、他の origin には返らない。
- **STUN**: 外から `iroh-relay.kukuri.app:3478` へ Binding Request を送ると、成功の応答（XOR-MAPPED-ADDRESS）が返った。
- **rollback 先**: `9c48cf34` の 4 image（[v0.3.3 の記録](./2026-09-30-v0.3.3-preview.1-release-rollout.md)）。

## Web クライアントの公開

- artifact は source `bba0b3af` から `cargo xtask-lite web-build` で作った（Docker の `kukuri-wasm-dev`、Node.js 22.12.0）。WASM は 22,376,191 bytes（1 file 25 MiB の上限の下）。
- Cloudflare Pages の project `kukuri-web` を LP と別に作り、preview で確かめてから本番の branch へ deploy した。custom domain `app.kukuri.app` は運営者が付けた。
- 確かめたこと
  - CSP は `_headers` と同じ、WASM は `application/wasm`、cookie なし、配信の HTML は build と同じ。
  - 初回の同意、本番の Community Node の規約の表示と同意（CORS が通る）、profile の保存。
  - Web から general に投稿した試しの投稿が、同じ topic のデスクトップ版（0.3.3）に本文まで届いた。Web の timeline には、本番のネットワークの既存の投稿が届いた。
- `kukuri.app` の zone の Cloudflare Web Analytics（RUM）の自動の差し込みが、HTML に計測の script を足していた（CSP が止めていた）。運営者が無効にし、差し込みが止まったことを確かめた。
- 見つけた不具合: いま offline の作者の profile が、同じ topic の参加者から中継されず「不明なユーザー」のまま（[#1619](https://github.com/kukuri-app/kukuri/issues/1619)）。
