## UI briefと作業

対象は、公開スレッドを作る人、投稿先でライブを始める人、配信者と視聴者。目的は会話からライブを始め、選んだ映像を大きく見ること。

開始は投稿フォームと公開スレッド作成Dialogに置く。既存の独立したライブ作成Dialogとそのglobal stateは投稿先を明示するDialogへ置き換える。ライブカラムの開始操作・初期の一覧は削除する。

拡大表示の初期値は全面表示。半分表示は横に並べ、狭幅では上下に並べる。映像の縦横比を保ち、映像領域の全幅・全高を使う。右側／下側には他の配信と公開スレッドの切替を置く。選択したライブの参加・終了、重ねる投稿とリアクションは保つ。

自分の映像は既存controllerの取り込みstreamを別のvideoで表示し、配信の寿命を表示componentへ移さない。カメラの許可を得た後に機器を列挙し、選択の変更で既存の取り込みを止めて選び直す。

状態は読込み中・取得失敗・終了・未参加・自分の配信前／配信中。既存の案内と再試行を使う。切替・表示だけでは参加や取り込みを始めない。キー操作・pointer・touchで同じ選択へ到達させる。確認条件はDesktop 1440×900とMobile 390×844、dark、英語／日本語。Tauri WebViewと実機Androidのカメラは自動試験と区別して記録する。

候補は既存の一覧・開始カラムを残す案と、開始を会話側へ集約する案。ユーザー指定に従い後者を採用し、旧導線を併存させない。サムネイルの共有に関わる区分Cの変更として、結合testと固定headの独立監査で判定する。
