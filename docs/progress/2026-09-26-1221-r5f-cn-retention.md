# #1221 R5-F: CN の保存と撤回台帳を一体で回収可能にする

## 完了境界

正本は [#1221](https://github.com/kukuri-app/kukuri/issues/1221) の R5-F と、2026-09-26 のユーザー決定「R5-F CNの受入下限と保持」。
区分 C、Scope revision `2026-09-24-outcome-v5-r2a-retention-1`、基準は #1370 merge `7c1d3cd5`。依存の R5-D・R5-E は完了済み。

- node の受入下限 W = max(現在 − T, 容量超過なら超過分（1 回最大 128 行）の古い行を越える時刻) を永続化し、単調に上げる。署名済み envelope の
  作成時刻が W 未満の投稿は全経路で索引しない。旧 `topic::` 経路でも索引の作成時刻と返信・repost の宛先を署名済み envelope に縛る。
- 撤回 marker は撤回対象の作成時刻を持ち、W を越えたら回収する（W 未満の投稿は再び索引へ入らない）。markerだけの TTL 削除や
  無制限 marker の移し替えはしない。
- 回収対象は索引の真実源と投影・撤回 marker・関係のアクション・参照されていない scan verdict・内容 scan cache。W 未満を古い順に
  1 回 128 件以内で消す。容量 B は 5 表の行数の合計。B と T は既定値の無い必須の運用設定（本番 T=30 日・B=1,000,000 行、T≥3 日）。
- 解除した scope は検索の gate が即座に外し、索引は 1 回 128 件以内で回収する（scope 全体の一括削除を撤去）。

対象外: CN の旧同期の iroh store（R5-I へ移管）、法務・運営の保存（moderation event・risk signal・送信防止・legal hold 等）、Dome の blob cache。

## 受入条件

| ID | 対象・期待結果 | 判定 |
| --- | --- | --- |
| AC-1 | 撤回 → marker の回収 → 撤回を持たない別 provider の旧応答で、撤回済みの投稿が索引へ戻らない。state の作成時刻を偽っても戻らない | 回収後の marker 0、旧応答と偽装の取込みで索引 0 |
| AC-2 | 容量を超えると W が上がり、計数が B 以下になるまで古い順に回収する。W 未満の投稿は容量に余裕ができても入らない | 計数 ≤ B、W の値、W 未満の挿入の拒否 |
| AC-3 | 解除した scope は検索から即座に外れ、索引は 1 回 128 件以内で回収される。撤回 marker は W まで残る | 解除直後の検索 0、各回 ≤ 128、marker 残存 |
| AC-4 | 回収は途中で止めても、永続化した W から同じ条件で続き、1 回の回収は常に 128 件以内。計数は実際の行数と一致する | 再接続後の継続、1,000 件で各回 ≤ 128、計数の一致 |
| AC-5 | B と T は必須の運用設定で、未設定・T<3 日では起動・生成しない | operator の検証、indexer の設定読み込み |

維持する条件: INVAR-1 索引の fail-closed（allow・非 critical・撤回・送信防止）を変えない。INVAR-2 法務・運営の保存を回収しない。
INVAR-3 索引行を参照している scan verdict を消さない。INVAR-4 回収で全件の走査・GC をしない（各表の索引の先頭から上限つき）。

## 入口と副作用

| ID | 対応 | 入口 → helper | 期待結果 / 禁止する副作用 |
| --- | --- | --- | --- |
| T1 | AC-1/2 | 索引行の INSERT/UPDATE → trigger `reject_known_withdrawn_entry` | marker または `created_at < floor` を 1 文で判定して拒否 |
| T2 | AC-1 | 撤回の検証（`scope_context`・`ReferenceGuard`）→ `record_verified_withdrawal(…, created_at)` → trigger `apply_verified_withdrawal` | 索引行を消し、W 未満なら marker を残さない |
| T3 | AC-1 | `ReferenceGuard::verify` | どの replica でも作成時刻・返信先・repost 元を署名済み envelope と照合 |
| T4 | AC-2/4 | worker の見直し → `IndexerParticipant::reclaim_retention` → `advance_retention_floor` → 投影 `remove_older_than` → `reclaim_expired` | 1 回 128 件以内、見直しあたり最大 16 回 |
| T5 | AC-3 | worker の見直し → `retire_scope` → 投影 `remove_scope_page` → `remove_scope_page` / `filter_surfaceable` | 見直しあたり合わせて 128 件以内、解除した scope は表示しない |
| T6 | AC-5 | `deploy.indexer_retention_days` / `indexer_capacity_rows` → tfvars → env → `configure_retention` | 未設定・T<3 日はエラー |

## 実装の照合（監査前）

- migration `202609260002_cn_retention`: `retention_state`（floor・units・capacity・retention_secs）、marker と関係のアクションの
  `created_at`（既存行は移行時刻 + 600 秒の上界）、5 表の計数 trigger と移行時の計数、verdict・scan cache・`index_entries.verdict_id`
  の索引、2 つの trigger 関数の置き換え。
- cn-core: `index_retention.rs`（`configure_retention`・`advance_retention_floor`・`reclaim_expired`）、`IndexEntryStore` の
  `remove_scope` → `remove_scope_page`、撤回 marker と判定に作成時刻、`filter_surfaceable` に supported の join、関係の
  アクションに `created_at`。
- cn-indexer: 投影の `remove_scope` → `remove_scope_page`・`remove_older_than`（ArcadeDB は `created_at` 索引と `DELETE … LIMIT`）、
  撤回の対象を作成時刻つきの map に、`ReferenceGuard` の照合を全 replica へ、`retain_supported_scope` の一括削除と
  `stop_and_deindex_scope`・`revoke_channel_and_deindex` の撤去、worker の段階回収、必須設定の読み込みと起動時の反映。
- 運用設定: cn-operator の検証と tfvars、terraform の変数・env テンプレート、compose、`.env.community-node.example`、runbook。
- ADR 0025 §9 に新しい判断と旧案（無期限の marker、scope の一括削除）の失効を記録。

## 検証（局所）

- 変更前に失敗する条件: 撤回 marker は無期限に増え、消せば古い provider の応答で撤回済みの投稿が戻る。旧 `topic::` 経路は
  state の作成時刻を署名で縛らない。scope 解除は scope 全体を 1 文で消す。保持期間・容量の設定が無い。
- Postgres（`KUKURI_CN_RUN_INTEGRATION_TESTS=1`）`retention_contracts`: AC-1（marker は署名済みの作成時刻を持ち、W を越えて
  回収後、旧応答・作成時刻の偽装とも索引 0。偽装の照合を外すと失敗することを確認）、AC-2（容量 200 に対し 300 行ずつ 5 回流入させ、worker と同じ 1 回の見直し（`reclaim_retention_pass`）ごとに計数が
  200 以下へ戻る。W 未満の挿入は拒否。超過分でなく 1 行ずつ進める形に戻すと失敗することを確認）、AC-3（300 行の scope を解除した直後に検索 0、各回 ≤128 の 6 回で回収、
  途中の再 support でも撤回は残る）、AC-4（1,000 行の期限切れを投影から先に 128 件ずつ、再接続後に同じ W で続けて回収し計数が一致）。
- ArcadeDB（使い捨てコンテナ）: `arcadedb_projection_reclaims_in_bounded_pages`（`remove_older_than` と `remove_scope_page` が上限
  つきで消し件数を返す）、`worker_writes_and_deindexes_real_arcadedb_projection`（解除した scope の実投影が段階回収で消える）。
- cn-operator `indexer_stack_requires_retention_settings`（未設定・T<3 日のエラーと tfvars）。
- 既存 test の調整: 検索の gate が supported の scope を要求するため、cn-core の索引の test は scope を support してから確かめる。
  worker の `deindexed` は従来どおり scope 単位で数える。indexer の設定 test は必須の 2 変数を置く。
- cn-core・cn-indexer・cn-user-api・cn-cli・cn-trust・cn-operator の test を Postgres・ArcadeDB つきで実行し、Valkey を要する
  rendezvous 5 件と、運用者ローカルの追跡外 `operator-config.yaml`（新しい必須 2 キーが未記入。CI には無い）を読む 1 件以外が成功。
  `cargo clippy --all-targets -D warnings`・`cargo fmt --check`。`oversized-files` は `cn-operator/src/config.rs` が必須設定 2 件と
  検証で 1324→1337 行（baseline を更新）。
- 本番反映（運用者設定への `indexer_retention_days: 30` / `indexer_capacity_rows: 1000000` の記入と apply）は、本番反映をまとめる
  別 Issue で行う。
- 監査の指摘（固定 head `ce6f9976`）への修正: 容量超過時の W の前進を「最古の 1 行」から「超過分（1 回最大 128 行）の古い行を越える
  時刻」へ変え、worker の見直しの回収を `reclaim_retention_pass` として test と同じ経路にした。CN image の smoke
  （`scripts/ci/cn_indexer_smoke.sh`）へ必須の 2 変数を渡す。
